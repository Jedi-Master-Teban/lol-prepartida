## Funciones (nombres y firmas exactas)
```python
def clasificar_dano(ataque: int, magia: int) -> str
def clasificar_alcance(rango_ataque: float) -> str
def generar_fichas(champion_json: dict, existentes: dict | None = None) -> dict[str, dict]
def leer_fichas(ruta: Path) -> dict[str, dict]
def escribir_fichas(fichas: dict[str, dict], ruta: Path) -> None
def version_mas_reciente(static_dir: Path) -> str
```

## Reglas
1. `clasificar_dano(ataque, magia)`: `"magico"` si `magia >= ataque + 3`; `"fisico"` si `ataque >= magia + 3`; si no, `"mixto"`.
   Se llama con `info.attack` e `info.magic` del campeón.
2. `clasificar_alcance(rango)`: `"cuerpo"` si `rango <= 300`, si no `"distancia"`. Se llama con `stats.attackrange`.
3. `generar_fichas(champion_json, existentes)`:
   - `champion_json` es el contenido de `champion.json`; los campeones están en `champion_json["data"]` (la clave de cada uno es su `id`, por ejemplo `"Ahri"`).
   - Devuelve un diccionario `{id: ficha}`.
   - Una ficha **nueva** tiene exactamente estos campos, en este orden:
     `dano`, `alcance`, `etiquetas_riot` (lista de strings, viene de `tags`), `enganche` (`""`), `control` (`""`), `escala` (`""`), `arquetipo` (`""`), `verificado` (`False`).
   - Si el campeón ya está en `existentes`: recalcula `dano`, `alcance` y `etiquetas_riot` desde Data Dragon y **conserva** de la entrada existente los campos `enganche`, `control`, `escala`, `arquetipo`, `verificado` y `fuente` (este último solo si existe; no lo inventes en fichas nuevas).
   - Las entradas de `existentes` que no están en Data Dragon se **conservan sin cambios** en el resultado.
   - No modifiques los diccionarios que recibes (haz copias).
4. `escribir_fichas(fichas, ruta)`:
   - Crea la carpeta de `ruta` si no existe.
   - Primera línea del archivo, un comentario: `# Fichas de campeones. `dano` es una aproximación (info.attack frente a info.magic de Data Dragon).`
   - Un bloque por campeón, **ordenados alfabéticamente** por nombre, así: una línea en blanco, `[Nombre]`, y una línea `campo = valor` por cada campo.
   - Orden de los campos: `dano`, `alcance`, `etiquetas_riot`, `enganche`, `control`, `escala`, `arquetipo`, `verificado`, `fuente`, y al final cualquier otro campo en orden alfabético. Solo se escriben los campos que la ficha tenga.
   - Valores: texto y listas de texto → `json.dumps(valor, ensure_ascii=False)` (eso ya produce TOML válido: `"magico"`, `["Mage", "Assassin"]`). Booleanos → `true` / `false` (en minúscula). Enteros → `str(valor)`. Atención: `bool` es subclase de `int` en Python, revisa `bool` **antes** que `int`.
   - Si el nombre del campeón no es solo letras, números, `_` o `-`, se escribe entre comillas con `json.dumps`.
   - Escribir dos veces lo mismo debe dar un archivo idéntico byte a byte.
5. `leer_fichas(ruta)`: lee con `tomllib`; si el archivo no existe devuelve `{}`.
6. `version_mas_reciente(static_dir)`: mira las subcarpetas de `static_dir` que contengan `champion.json` y devuelve el nombre de la mayor **comparando números, no texto** (`"16.22.1"` es mayor que `"16.9.1"`: usa `tuple(int(x) for x in nombre.split("."))`). Si `static_dir` no existe o no hay ninguna, lanza `FileNotFoundError`.
